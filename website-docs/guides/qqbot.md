# 故事熔炉 bot 使用说明

故事熔炉 bot 是 QQ 群内的 StoryForge 项目助手，提供**项目答疑、更新通知和文字生图**。本文适用于已加入机器人、由维护者完成配置的群，按 **2026 年 10 月 12 日**运行功能核对。

这是独立运行的群助手。群成员不需要填写模型 API 密钥；它也不能读取或操作你在 StoryForge 应用中保存的作品。应用内的模型设置仍见[模型与 API 配置](/getting-started/model-config)。

## 1. 怎么叫机器人

在 QQ 输入框输入 `@`，从成员列表选择 **“故事熔炉bot”**；也可以输入“故事”“熔炉”等关键字寻找，再选择机器人。然后输入问题或指令。

**必须实际选择机器人。** 单纯复制下面示例中的 `@故事熔炉bot` 文字，可能不会触发。普通聊天不会让机器人主动插话；提问和使用指令都需要先 @它。

## 2. 项目答疑

直接 @机器人提问，不需要额外指令。例如：

```text
@故事熔炉bot StoryForge 是什么？新手怎么开始？
@故事熔炉bot 怎么配置模型？
@故事熔炉bot 怎么备份和导出作品？
@故事熔炉bot 最近更新了哪些功能？
```

答疑范围包括项目介绍、功能与限制、入门、安装、模型配置、备份导出、常见故障和开发进展。遇到故障，请说明**具体功能、操作步骤和报错文字**。

普通答疑当前只处理单条问题的前 **1000 个字符**。长故障记录请先概括问题，再分次补充必要信息；生图描述不受这一项限制。

机器人可以结合最近 **10 分钟内的相关群聊**理解上下文，但不会完整记住全部讨论，也没有长期聊天记忆。答疑以公开知识库与 GitHub 资料为依据，群成员的说法不能代替已核实的项目事实。

资料同步存在时间差，回答也可能有误。主干代码更新、发布新版本、官网部署是不同状态，不能把回答当作功能已经上线的承诺。

## 3. 公开指令

所有指令都需要先 @机器人。

| 指令 | 用途 |
| --- | --- |
| `/帮助` | 查看普通成员使用说明和指令 |
| `/状态` | 查看答疑开关、更新订阅和知识库同步状态 |
| `/最新` | 查看最近同步的 GitHub 主干、发布包和官网更新记录 |
| `/生图 描述` | 根据完整文字描述生成一张图片 |

例如：`@故事熔炉bot /最新`。

## 4. 文字生图

### 基本用法与尺寸

```text
@故事熔炉bot /生图 一只橘猫坐在窗边看星空，绘本风格，无文字
@故事熔炉bot /生图 16:9 一座云海上的浮空城，晨光，电影感
@故事熔炉bot /生图 4K 2:3 成年人物穿深蓝色风衣，全身，双脚与鞋子完整入画，写实摄影
```

- 每次生成 **一张图片**，直接发图，不发图片链接。
- 未指定时，**比例按描述自动选择，尺寸默认 2K**。可指定 `1K、2K、3K、4K`；尺寸与比例可以交换顺序。
- 支持比例：`1:1、16:9、9:16、3:4、4:3、2:3、3:2、21:9`。这些是模型支持的比例和尺寸档位，不承诺任意精确像素尺寸。
- **机器人不设置提示词字数上限，也不会主动截断生图描述**；仍受 QQ 单条消息与模型服务本身的限制。太长时，优先写清必要要求，避免重复或矛盾。
- 兼容 `/生图，描述`、`/生图：描述`。仍须使用 `/生图` 指令，只说“帮我画一张”不会启动生图。
- 当前仅支持**文字生成图片**，不支持上传参考图改图，也不会自动把群聊上下文或群内图片加入生图描述。请在每次指令里写清完整需求。

### 自动细化提示词

生成前，机器人会补齐未说明的构图、比例、风格、背景、光线和画质要求，完整保留原始描述，**用户明确要求优先**。

例如，人物描述包含高跟鞋、鞋袜或腿部展示，又没有指定景别时，会优先补成全身构图；明确写了“半身像”，就会保留半身。若鞋子必须出现，请直接写“全身、双脚和鞋子完整入画”，不要同时写“半身像”。

细化服务失败时，会使用基础模板继续生成，并在结果说明中标明。细化与生图都由 Agnes 模型服务处理，不能保证每张图片都准确呈现全部细节。

### 排队与结果归属

收到“**已加入生图队列**”并带任务编号，才表示任务已被受理。提示会显示前面还有多少任务。

- 同一个人可以连续提交**不同描述**，例如分别提交橘猫、黄猫、黑猫，不需要等上一张完成。
- 全局一次生成一张图片，按收到的顺序处理；**每人同群最多 5 个未完成任务、本群最多 10 个、全局最多 20 个**。
- 同一成员的相同描述正在排队或生成时，不重复受理；受理后 60 秒内也有防重复间隔。不同描述不受这个间隔限制，不同成员可以分别提交相同描述。
- 重复或队列满时，机器人会说明原因并提示“**这次请求未加入队列**”。这种请求不会之后自动补排，需要满足条件后重新提交。原因提示每人最多 30 秒一次，反复刷同一请求不会不断提示。
- 完成后，**图片、任务编号、描述摘要和提交者昵称（QQ 提供时）合成一条图文结果**。当前使用普通昵称标明归属，没有可靠的 QQ 原生 @ 提醒或原消息引用；请按任务编号和描述核对图片。

排队时间另计；细化和生成可能需要几十秒或更久，不是即时返回。不要因尚未出图重复提交同一任务。排队过长还可能超过 QQ 允许回复原指令的时间，最终能否送达取决于平台权限与限制。

### 上传与发送失败怎么办

| 提示或情况 | 含义与处理 |
| --- | --- |
| 正在补传一次 | 图片已经生成，上传 QQ 遇到临时网络错误；机器人会补传同一张图片一次，请稍等 |
| 图片已生成，但上传 QQ 失败 | 上传仍未成功，图片未发到群里，任务已经结束；稍后可重新提交 |
| QQ 拒绝发送，附错误码 | 生成与上传已完成，但最后发群被平台拒绝；任务结束，可调整描述后重新提交或向维护者提供任务编号与错误码 |
| 生图处理结果不确定 | 生图接口等步骤没有返回可确认结果；不会自动重新生图，请稍后核对群消息再决定是否重提 |
| 没收到回复 | 确认实际 @到了机器人、使用 `/生图`；再看排队与拒绝提示，稍等后查询 `/状态`，避免连续重复发送 |

临时上传故障最多补传一次，每次上传最多等待 60 秒；补传只复用已生成的图片，**不重新生图**。权限、额度或明确拒绝不自动补传；最终发群结果不确定时，也不会盲目重发。明确失败后解除本次描述的防重复限制，后续队列继续处理。若维护者暂停服务，或生成中的任务遇到重启，部分任务可能停止且不会自动重新生成。

## 5. 更新通知与资料同步

本群由维护者开启更新订阅后：

- 每天 **北京时间 20:00** 检查知识库更新日志，有新增记录才发通知。
- GitHub 主干和发布包更新另行检查，正常约每 **5 分钟**一次。
- 不补发订阅前的历史更新；仅修改旧日志正文，不会触发新增记录通知。
- QQ 需要允许机器人主动发送；通知是否送达还受平台权限和发送限制影响。未收到通知时，可 @机器人使用 `/最新` 主动查询。

答疑资料约每 **30 分钟**完整同步一次，更新日志页面正常约每 **5 分钟**刷新。网络故障时保留此前资料；明显超时会提醒资料可能滞后。新上传到知识库的说明不保证立即进入答疑索引。

## 6. 防刷屏与隐私

- 不设每日答疑次数上限。普通答疑**同群间隔 10 秒、同一成员间隔 15 秒**，并有队列与发送限速保护；过密请求可能直接忽略。
- 生图使用上面的独立排队与重复保护规则；上传补传不会再调用生图模型。
- 机器人所有群内文字消息都不发链接，资料来源只显示文档名称。本页网页链接供在知识库阅读使用。
- 最近 10 分钟的普通群聊临时保存在服务器内存中，过期清理、重启清空，不保存长期群聊历史。等待处理的 @问题和生图描述会短暂进入服务器私有任务队列，完成或结束后删除原文；任务编号、状态、发送记录以及部分任务的提交者昵称等运行记录仍会保留。
- 答疑时，**当前问题、相关群聊片段和公开资料会发送给 Agnes**；生图时，文字描述会发送给 Agnes 进行细化和生成。生成图片在内存中流转，并上传 QQ 用于发群，不写入官网或项目知识库。需长期保留图片时，请自行保存 QQ 中收到的图片。

**请勿发送 API 密钥、密码、私有手稿或其他敏感信息。** 机器人不能替大家操作服务器、修改项目、执行管理任务，也不能直接访问个人作品或本地文件。群助手的生图能力不代表 StoryForge 网页应用自动获得相同服务。
