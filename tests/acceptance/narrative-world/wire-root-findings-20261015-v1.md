# NW-2E · 封存原字节与语义摘要的合并核对

本次只改世界引擎 S1 冻结 v4 内容的确定性校验。语义 owner、封存格式、编译器版本、原文、权限、来源闭包和三注册表保持原合同。没有模型调用、作者数据写入或新的采纳路径。

冷开读取原先先逐段核对规范文本，再遍历相同内容计算语义根摘要。现在同一严格遍历同时完成两项工作，只在根层排除 `semanticRootHash` 与 `indexDescriptor`；这两个字段仍参加完整原字节核对和 JSON 合法性检查，同名嵌套字段仍进入语义摘要。对象形式的输入继续复制后校验。原文投影、索引重建、权限、证据和最终哈希比较仍全部执行。

9 项新反例通过：根与嵌套排除范围、数值键和 Unicode 排序、空对象与全排除、特殊属性、非规范文本、被排除字段中的非法值、长字符串边界及调用间修改。定向检查和基线回读合计覆盖 12 个不同文件、173 项不同检查；重复执行的基线不重复计数。v30 保存 227 个输入 hash，原查询、影响分析和领域观察未改变。完整 lint、类型检查和构建通过。

[逐次原始测量](./raw/nw2e-wire-root-20261015-v1/paired-root-digest-diagnostic.json)使用十万字符、1050 条语义记录、4000 条边的确定性合成工程材料。两种算法对相同的已解析冻结内容交替执行 8 组，共 16 次；所有字节核对和语义摘要一致。旧两步处理耗时中位数 178.70ms，合并处理 128.52ms；逐组耗时比的中位数为 **0.752**。完整封存内容及索引 hash 与历史十万字材料相同。

这是 Node 中单个阶段的局部诊断。它排除了 JSON 解析、来源投影、索引编译，没有测浏览器端到端冷开或峰值内存，后台负载也未受控；因此不能外推百万字性能已达标。既定 3s 冷开、256MiB 附加峰值和 5 冷/30 热次数保持不变。改动前的 CPU 采样包含编译后的体积核对与打包，只用于定位耗时来源，不能当纯编译时长分解。

[结构化回执](./wire-root-diagnostic-20261015-v1.json)保留逐次时间、准确源码、初次旧指纹不匹配和测试写法 lint 失败；后两项已通过新版本基线回读及完整 lint 处理。当前 r7/r8 完整 CI 与原生检查使用更早的冻结源码，不覆盖本增量。当前源码的完整 CI、原生读取测量、本地提交、生产影响精度、独立语义评审与作者抽检仍待完成；原未知模型结果没有重发或改判。
