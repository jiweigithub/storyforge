# 冻结来源标题向模型材料传递的修复

2026-10-15；对应 [实际检查回执](./reader-provenance-20261015-v1.json) 与基线 v33。属于 S1 世界引擎研发的只读增量，作品/世界继续拥有原文，没有新增表、采纳字段、媒资或产品运行数据。

## 解决的问题

此前标题搜索能够找到章节，但结果的语义名称只有“已确认揭示”，读者无法确认它来自哪一章。当前实现从同一份已验证冻结 release 提取 `authorSource`，通过 typed query、provider descriptor、分层读取、Gateway 实际原文包和注册模型读取工具传递。`authorSource` 明确是目录元数据，不是故事断言或原文引文。

语义标题、原子、精确引文和 descriptor 内容身份保持；作者用途的读取策略更新为 v3，分页解释更新为 v3。元数据占用查询和实际上下文预算。来源标题不取自题目、gold 或活动草稿；重命名草稿不会改变冻结出处。读者、角色和产品用途没有获得作者目录，精确资源限制与撤销继续生效。

新收集的评测材料将冻结出处写入读者可见的目录标签，并另外保存结构化出处。生产语义名称保持不变，原 reader 脚本、协议、输入和模型响应全部保留；8 个运行脚本/注册项的 hash 与既有真实批次一致。本次没有调用模型，也没有重发旧失败或未知输入。

## 实测与限制

- 12 个原场景的章节标题都经过实际 provider 和历史 reader 消息构造器，已确认模型材料包含冻结出处；这只证明信息抵达，不是新的回答正确率。
- 14 文件/111 项定向测试通过，覆盖类型查询、原文与持久证据、作者/角色/产品权限、完整元数据预算、两产品精确来源计划和历史评测保护。其中一项包装执行 52 个 Node 反例，不重复累计。
- 新基线 25 项通过，原 120 查询/48 修改的观察未变，238 个来源指纹一致。完整 TypeScript、改动文件 lint、架构、表注册、AI 手册和入口登记检查通过。
- 首次反例运行及两次中间失败日志保留。中间失败包括测试遗漏必填读取约束，以及修改 reader 解释器被历史 hash 保护拒绝；随后恢复解释器原字节，只调整新材料。没有放宽历史校验。
- 原设计副本的 7229 个任务文件保持，供已排队的规模测量使用；修复发生在独立副本。r9 验证只覆盖 v22/v30，旧设计副本的 compiler-v2 诊断只覆盖 v24/v32，均不包括此增量。
